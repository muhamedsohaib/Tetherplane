## 1. Executive Summary

The Control Portal and Security Remediation Gate work on `feat/universal-permissions-control-portal` hardens end-to-end authentication, authorization, transport security, and state persistence across Rust (`tether-core`, `tetherd`), TypeScript Relay (`relay`), Browser Bridge (`browser/bridge`), and the Chrome Extension Host:

- **Positive Owner Allowlist & Authorization Separation (F-1, F-2):** Replaced prefix blocklisting with positive owner verification ([`isAuthorizedOwnerIdentity`](../../relay/src/auth/static-auth.ts#L51-L74) + Rust [`SynchronizedDevicePolicy::resolve_principal`](../../agent/tether-core/src/principal.rs#L324-L352)), explicit `role: "owner" | "operator"` config support across static/OIDC authenticators, and owner-only enforcement on `/pair/approve`, `/devices`, `/devices/:id/revoke`, and [`ensureDevicePolicy`](../../relay/src/policy/policy-store.ts#L534-L614).
- **Zero Inline HTML Sinks & Cookie/Origin Hardening (F-3):** Eliminated DOM XSS via strict `createEl()` DOM construction (`textContent`), hashed strict CSP (`default-src 'none'`), `HttpOnly; SameSite=Strict` cookies exchanged over `POST /portal/api/session` with `X-Tetherplane-Csrf`, explicit `--public-origin` / `--trust-proxy-headers` support for TLS-terminating reverse proxies (ignoring arbitrary `X-Forwarded-*` headers), and mandatory `Origin`/`Referer` presence on cookie-authenticated mutations.
- **Policy Consistency & Fail-Closed Agent State (F-4):** Prevented owner/operator ID collisions in `POST /portal/api/operators`, denied rollback on revoked devices, validated all capability arrays against the 49 canonical MCP operations, required `--state-dir` whenever `tetherd` runs with `--relay-url`, and made `tetherd` startup fail closed on corrupt, invariant-invalid, or wrong-device `synchronized-policy.json`.
- **Resource Bounds & Anti-Abuse Throttling (F-5):** Added proactive expired-pairing pruning and bounded queue capacity (`DEFAULT_MAX_PENDING_PAIRINGS = 128`), sliding-window `429` + `Retry-After` rate limiting on `/pair/start`, `/pair/approve`, and `/portal/api/session`, and bounded in-memory audit history (`DEFAULT_MAX_AUDIT_HISTORY = 500`).
- **Local Browser Bridge Hardening (F-6):** Restricted Browser Bridge WebSocket upgrades to valid `chrome-extension://<32-char-id>` origins (and pinned `expectedExtensionId` when present), bound `hello.extension_id` to the verified upgrade `Origin`, and standardized shared-secret checks on SHA-256 + `timingSafeEqual`.
- **Universal Defaults & Explicit Coexistence Warnings (F-7):** Preserved universal owner defaults across all 6 Compact MCP tool families (`allow_destructive = true`, while human-origin `process.terminate` and unshared human tabs/windows remain blocked) and updated Portal modals, tooltips, and staging docs to clarify destructive auto-approval and `Lift Emergency Lockdown` (baseline Universal restore) vs. Recoverable Snapshot Rollback.

## 2. Domain-by-Domain Verification Matrix

### 2.1 Authentication & Transport Binding

- **Static & OIDC Relay Clients**:
  - [`StaticClientAuthenticator`](../../relay/src/auth/static-auth.ts#L76-L107) stores only SHA-256 hashes of bearer tokens in memory and [`parseClient`](../../relay/src/cli-config.ts#L212-L285) rejects raw tokens inside auth JSON config files (requiring `token_env` indirection) while validating optional `role: "owner" | "operator"` against [`validateConfiguredIdentityRole`](../../relay/src/auth/static-auth.ts#L36-L49).
  - [`OidcClientAuthenticator`](../../relay/src/auth/oidc-auth.ts#L34-L221) enforces HTTPS `issuer`, `audience`, and `jwksUri`, `RS256`, required `exp`/`sub` claims, required configured scopes, exact agreement between `azp` and `client_id` when both appear, role validation on bindings and subject identity configs, and explicit binding/subject-prefix mapping without trusting caller-supplied account/principal claims.
- **Device WebSocket Authentication**:
  - [`DeviceWebSocketGateway`](../../relay/src/devices/ws-gateway.ts#L81-L125) and [`DeviceRegistry.authenticateDevice`](../../relay/src/devices/registry.ts#L152-L176) authenticate devices via `Authorization: Device <secret>` + `x-tetherplane-device-id`, enforce secret length `>= 16`, verify SHA-256 digest using `timingSafeEqual`, reject revoked bindings (`revokedAt !== null`), and terminate superseded (`4000`) or revoked (`4001`) WebSockets cleanly.
  - [`tetherd`](../../agent/tetherd/src/relay_ws.rs#L60-L71) requires `wss://` by default, permits `ws://` only with explicit loopback flag `--relay-allow-insecure-localhost`, and requires [`--state-dir`](../../agent/tetherd/src/main.rs#L123-L138) whenever `--relay-url` is configured.
- **MCP Session Identity Binding**:
  - [`RemoteMcpHttpGateway`](../../relay/src/mcp/http-gateway.ts#L147-L168) binds each `mcp-session-id` to the initializing `ClientIdentity` (`sameIdentity`), returning HTTP `403` on cross-identity reuse on both POST and GET/DELETE handlers ([lines 218-245](../../relay/src/mcp/http-gateway.ts#L218-L245)).
- **Browser Extension Local Bridge**:
  - [`startExtensionPairingBroker`](../../browser/bridge/src/pairing.ts#L38-L100) listens only on `127.0.0.1`, restricts CORS and `POST /pair` to `Origin: chrome-extension://<32-char-id>` matching `body.extension_id` (and pinned [`browser-extension.id`](../../scripts/browser-extension-host.ts#L106-L139)), and enforces single-use pairing (`410 pairing_consumed`).
  - [`startExtensionBridgeServer`](../../browser/bridge/src/extension-session.ts#L91-L237) validates WebSocket upgrade `Origin` (`^chrome-extension://([a-p]{32})$`) and dynamic [`expectedExtensionId`](../../scripts/browser-extension-host.ts#L61-L67), verifies `hello.extension_id === originExtensionId`, compares `launchToken` via SHA-256 `timingSafeEqual` ([lines 308-312](../../browser/bridge/src/extension-session.ts#L308-L312)), and closes (`4003 sensitive_data_forbidden`) on cookie, password, or authorization-header keys; [`rpc-server.ts`](../../browser/bridge/src/rpc-server.ts#L419-L429) uses the same SHA-256 `timingSafeEqual` token check.

### 2.2 CSRF, XSS, Content Security Policy & Browser Headers

- **Zero Inline HTML Sinks**: [`portal-ui.ts`](../../relay/src/portal/portal-ui.ts#L654-L683) constructs all dynamic DOM nodes via `createEl()` (`createElement`, `.textContent`, `dataset`), with no `innerHTML` / `outerHTML` / `insertAdjacentHTML` / `eval` sinks, verified by adversarial Chromium tests ([`tests/e2e/portal-security-browser.test.ts`](../../tests/e2e/portal-security-browser.test.ts)).
- **Strict CSP & Hardening Headers**: [`PORTAL_CONTENT_SECURITY_POLICY`](../../relay/src/portal/portal-ui.ts#L1692-L1702) sets `default-src 'none'`, SHA-256 hashes for inline script and stylesheet, `connect-src 'self'`, `img-src 'self' data:`, `form-action 'self'`, `frame-ancestors 'none'`, `base-uri 'none'`, `object-src 'none'`. [`RelayControlHttpGateway`](../../relay/src/devices/control-http.ts#L183-L199) adds `Cache-Control: no-store`, `X-Content-Type-Options: nosniff`, `X-Frame-Options: DENY`, `Referrer-Policy: no-referrer`, `Cross-Origin-Opener-Policy: same-origin`, and `Cross-Origin-Resource-Policy: same-origin`.
- **CSRF & Trusted Reverse-Proxy Origin Defense**: Non-GET/HEAD cookie-authenticated portal API calls require both [`#verifySameOriginHeaders`](../../relay/src/devices/control-http.ts#L939-L998) (`Sec-Fetch-Site !== cross-site`, mandatory `Origin` or `Referer` matching direct `Host` protocol or explicitly configured [`--public-origin`](../../relay/src/cli-config.ts#L30-L58) and optional `--trust-proxy-headers`) and constant-time `X-Tetherplane-Csrf` validation ([lines 876-887](../../relay/src/devices/control-http.ts#L876-L887)). Unconfigured `X-Forwarded-*` headers are ignored.

### 2.3 Session Handling

- **No URL Query Tokens or Client Storage**: [`hasQueryTokenParameter`](../../relay/src/devices/control-http.ts#L1016-L1030) rejects `token`, `access_token`, `bearer`, `auth`, and `authorization` query parameters on `/portal` and `/portal/*` with HTTP `400` ([lines 166-181](../../relay/src/devices/control-http.ts#L166-L181)). Client login [`connectSession`](../../relay/src/portal/portal-ui.ts#L864-L892) clears the password input before issuing `POST /portal/api/session` with `Authorization: Bearer ...`, keeping CSRF token strictly in closure memory.
- **Cookie Security Attributes & Teardown**: [`formatSessionCookieHeader`](../../relay/src/devices/control-http.ts#L1047-L1063) issues `HttpOnly; SameSite=Strict; Path=/portal; Max-Age=28800` and sets `Secure` whenever direct TLS (`--tls-cert`/`--tls-key`) or an `https://` `--public-origin` is active ([`server.ts:152-154`](../../relay/src/server.ts#L152-L154)). Sessions use 256-bit random IDs (`randomBytes(32)`), cap at `MAX_PORTAL_SESSIONS = 256` ([`control-http.ts:910-924`](../../relay/src/devices/control-http.ts#L910-L924)), expire after 8 hours, and immediately terminate associated `/portal/api/events` SSE sockets on logout ([lines 381-402](../../relay/src/devices/control-http.ts#L381-L402)) or expiry ([lines 677-725](../../relay/src/devices/control-http.ts#L677-L725)).

### 2.4 Principal Isolation & Dual-Layer Enforcement

- **Positive Owner Validation**: Both Relay [`#requireOwnerBearerIdentity`](../../relay/src/devices/control-http.ts#L824-L841), [`#requireOwnerIdentity`](../../relay/src/devices/control-http.ts#L843-L901), and [`PolicyStore.evaluateAndRecordInvocation`](../../relay/src/policy/policy-store.ts#L1154-L1205) enforce [`isAuthorizedOwnerIdentity`](../../relay/src/auth/static-auth.ts#L51-L74), requiring `principalId === "human:" + accountId` or explicit `role: "owner"` (while blocking reserved prefixes `operator:`, `external:`, `guest:`, `unpaired:`, `service:`, `client:`). Pairing approval, device listing, and device revocation ([`control-http.ts:220-285`](../../relay/src/devices/control-http.ts#L220-L285)) require owner authorization and pass full `ClientIdentity` to [`ensureDevicePolicy`](../../relay/src/policy/policy-store.ts#L534-L614).
- **Relay Identity Pinning**: [`DeviceRouter.call`](../../relay/src/routing/device-router.ts#L204-L212) overwrites caller-supplied `principal_id` and `actor` from the authenticated `ClientIdentity` (`principal_id: identity.principalId`, `actor: { id: identity.clientId, kind: "ai_client" }`), preventing client spoofing inside tool arguments.
- **Local `tetherd` Authority Boundary**: [`AgentRuntime::execute`](../../agent/tetherd/src/runtime.rs#L385-L388) binds `bound_principal_id` if launched with `--principal-profile`, and [`LocalPolicyBroker::evaluate_synchronized_policy`](../../agent/tether-core/src/policy.rs#L235-L345) independently evaluates synchronized policies (`emergency_lockdown`, [`resolve_principal`](../../agent/tether-core/src/principal.rs#L324-L352), device match, explicit denies, family/op grants, principal `allowed_roots`, global `allowed_directories`, and human-origin process termination) before executing any provider action. Unregistered principals fail closed on both relay (`PolicyStore.evaluateAndRecordInvocation`) and `tetherd` (`SynchronizedDevicePolicy::validate_invariants` + `resolve_principal`).

### 2.5 Default Universal Permissions & Explicit Overrides

- **Owner Default at Pairing**: [`ensureDevicePolicy`](../../relay/src/policy/policy-store.ts#L534-L614) and [`SynchronizedDevicePolicy::universal_for_owner`](../../agent/tether-core/src/principal.rs#L245-L265) assign `revision: 1`, `profile_id: "universal"`, `universal_permissions: true`, and all 6 families (`device`, `files`, `process`, `browser`, `desktop`, `batch`) to owner-paired devices.
- **Explicit Deny Precedence**: Both [`evaluatePermissionSet`](../../relay/src/policy/policy-store.ts#L415-L443) and [`PrincipalPermissionSet::evaluate_capability`](../../agent/tether-core/src/principal.rs#L169-L203) evaluate `denied_capabilities` first and `denied_families` second — overriding `universal_permissions`, `allowed_capabilities`, and `allowed_families`.
- **Canonical Schema Integrity**: [`CANONICAL_OPERATIONS_BY_FAMILY`](../../relay/src/policy/policy-store.ts#L32-L93) enumerates all 49 verified MCP operations (phantom ops such as `filesystem.delete` remain absent), and [`parsePolicyMutation`](../../relay/src/devices/control-http.ts#L1080-L1141) / [`assertCanonicalCapabilities`](../../relay/src/policy/policy-store.ts#L105-L116) reject non-canonical operations across device, global, and operator policy mutations.
- **Human Resource Protection**: Human-origin `process.terminate` stays unconditionally blocked ([`policy.rs:375-386`](../../agent/tether-core/src/policy.rs#L375-L386)), and background coexistence continues to protect unshared human tabs/windows ([`desktop_provider`](../../agent/tetherd/src/runtime.rs#L128-L160), [`browser/bridge`](../../browser/bridge/src/rpc-server.ts)).

### 2.6 Policy Revision Monotonicity & Rollback Security

- **Strictly Increasing Revisions**: All relay mutations (`updateDevicePolicy`, `upsertOperatorPolicy`, `removeOperatorPolicy`, `rollbackDevicePolicy`) compute `nextRevision = Math.max(desiredRevision, appliedRevision ?? 0) + 1` ([`policy-store.ts:825-826, 972-973, 1039-1040, 1114-1115`](../../relay/src/policy/policy-store.ts#L825-L826)).
- **Forward-Only Rollback**: Rolling back checks `binding.revokedAt === null` on both HTTP ([`control-http.ts:577-609`](../../relay/src/devices/control-http.ts#L577-L609)) and store ([`policy-store.ts:1086-1152`](../../relay/src/policy/policy-store.ts#L1086-L1152)) layers, selects an immutable historical snapshot (with `rev 1` per-device baseline preserved indefinitely across `MAX_RECENT_SNAPSHOTS_PER_DEVICE = 120` pruning at [`retainSnapshotsForPersistence`](../../relay/src/policy/policy-store.ts#L1773-L1796)), and mints a **new higher monotonic revision**, preventing stale policy replay.
- **Agent Anti-Rollback & Fail-Closed Durable Persistence**: [`AgentRuntime::validate_synchronized_policy`](../../agent/tetherd/src/runtime.rs#L260-L346) enforces [`validate_invariants`](../../agent/tether-core/src/principal.rs#L274-L321) and rejects `revision == 0`, mismatched `device_id`, `revision < existing.revision`, and conflicting payloads at `revision == existing.revision`, returning `policy_ack { applied: false, currentRevision }` ([`relay_ws.rs:250-277`](../../agent/tetherd/src/relay_ws.rs#L250-L277)). Policies persist atomically via temp file + `sync_all` + Windows-retried `rename` into `<state_dir>/policy/synchronized-policy.json` ([`runtime.rs:511-595`](../../agent/tetherd/src/runtime.rs#L511-L595)), and [`load_persisted_policy`](../../agent/tetherd/src/runtime.rs#L446-L509) fails closed on unreadable, corrupt, invariant-invalid, or wrong-device state files. Relay persistence (`DeviceRegistry`, `PolicyStore`) serializes atomic temp-write + Windows-retried `rename` via [`SerializedJsonFileWriter`](../../relay/src/persistence/atomic-json.ts), and reconnect via `device_hello` does not push backward when device revision exceeds relay desired revision ([`policy-store.ts:648-711`](../../relay/src/policy/policy-store.ts#L648-L711)).

### 2.7 Emergency Lockdown Security

- **Pre-Emptive Enforcement**: `emergency_lockdown == true` is checked before principal resolution, universal grants, and allowed operations on both the relay ([`policy-store.ts:1206-1235`](../../relay/src/policy/policy-store.ts#L1206-L1235)) and local `tetherd` ([`policy.rs:240-251`](../../agent/tether-core/src/policy.rs#L240-L251)), blocking owner and operator access across all 6 families and persisting across device restarts.
- **Confirmed Invocation & Recovery**: Both [`POST /portal/api/global/apply`](../../relay/src/devices/control-http.ts#L462-L487) and [`POST /portal/api/global/emergency-revoke`](../../relay/src/devices/control-http.ts#L489-L537) require `confirm: true`. `Lift Emergency Lockdown` (`restore: true`) explicitly restores baseline `Universal Access`; Portal UI copy ([`portal-ui.ts:1135-1146, 1620-1634, 1763-1766`](../../relay/src/portal/portal-ui.ts#L1620-L1634)) directs owners to Recoverable Snapshots & Rollback when prior custom restrictions should be reinstated.

### 3.2 Theoretical / Operational Concerns (Separate from Verified Source Defects)

1. **T-1 — Relay Plaintext Payload Visibility**: As documented in [`docs/security/remote-plane.md`](remote-plane.md) and [`docs/security/threat-model.md:27-30`](threat-model.md#L27-L30), the relay terminates client HTTPS and device WSS connections and forwards plaintext canonical invocations/results without an end-to-end payload encryption layer. Self-hosting and infrastructure isolation mitigate exposure.
2. **T-2 — Ephemeral In-Memory Portal Sessions**: `#portalSessions` lives solely in Node process memory (`MAX_PORTAL_SESSIONS = 256`, FIFO eviction on overflow at [`control-http.ts:910-914`](../../relay/src/devices/control-http.ts#L910-L914)). Relay restarts log out all portal browsers, and horizontal scaling without sticky sessions/shared session storage would fail session validation.
3. **T-3 — Equal-Privilege OS Malware (Out of Scope)**: Consistent with [`docs/security/threat-model.md:31-38`](threat-model.md#L31-L38), loopback TCP endpoints (`17657`), token files, and `synchronized-policy.json` assume OS-user account isolation and do not defend against malicious code already running with equal or higher OS privileges under the same Windows user.
4. **T-4 — MV3 Extension Restart Session Lifetime**: Because [`extension/browser/src/background.ts`](../../extension/browser/src/background.ts#L28-L35) intentionally keeps the launch token in `chrome.storage.session` rather than persistent storage on disk, closing Chrome completely requires re-pairing via the popup (`Pair with local Tetherplane`), whereas service-worker idle sleep reconnects automatically.
5. **T-5 — Staging vs. Production Host Collision**: Running default scripts such as [`scripts/live-acceptance.mjs`](../../scripts/live-acceptance.mjs), [`scripts/install-authenticated-browser-windows.ps1`](../../scripts/install-authenticated-browser-windows.ps1), or [`scripts/install-windows.ps1`](../../scripts/install-windows.ps1) on a machine that already hosts production Tetherplane agents would overwrite `%LOCALAPPDATA%\Tetherplane` tokens/binaries, bind production ports `17656–17658`, or touch `HKCU\...\Run` / Scheduled Tasks. Staging acceptance **must** follow the isolated procedure in [`windows-staging-acceptance.md`](../release/windows-staging-acceptance.md).
